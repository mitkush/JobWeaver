# Source Adapters behind a registry, with per-source fallback

Each Source is one module implementing a fixed interface and registering itself. The interface has two fetch modes. **Windowed** Sources (LinkedIn, Naukri, aggregators, boards, HN) return Postings for a query and a time window, so they only ever show new jobs. **Snapshot** Sources (company ATS Boards such as Greenhouse and Lever) return the full list of open jobs for one company, which is compared with stored Postings to find new, changed and closed jobs. Both normalise raw data into Postings and report credits used. Adding a Source is one new module plus one import line, never an `if source == ...` branch in core code. Every Fetch Run is isolated: if a Source fails for any reason (service down, rate limit, credits or tokens exhausted, blocked, unexpected format), the run marks it Degraded, keeps the Postings already fetched from other Sources, and retries it on the next scheduled run. One failing Source never stops the rest.

**Considered and rejected:** a single pipeline that fails as a whole (one flaky free tier would blank the Feed), substituting a "backup" Source for a failed one (Sources are not interchangeable; jobs only on LinkedIn are simply missed while it is down, and the UI says so).

**Consequences:** closed jobs can only be detected on snapshot Sources, so windowed-only Jobs expire by an age limit (default 30 days after posting) unless a snapshot Source still lists them, plus an apply-link check before drafting; Source Status is a first-class screen; every adapter has recorded-fixture tests for success, limit-exceeded and malformed responses; all Sources ship in V1 and free-tier limits are discovered at run time rather than verified up front.
