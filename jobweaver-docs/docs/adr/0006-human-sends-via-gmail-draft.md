# JobWeaver never sends; the User sends from Gmail

Nothing leaves JobWeaver on its own. "Save draft" only saves. The outward action is **Open in Gmail**: JobWeaver creates a real Gmail draft with the Tailored Resume attached (Gmail API, `gmail.compose` scope), and the User reviews, reformats and sends it inside Gmail. The Google OAuth app runs in testing mode with the External user type: up to 100 named test users, no Google verification, and an "unverified app" warning that test users click through. Checked on 5 Oct 2026: in this mode, refresh tokens and consents for scopes beyond basic profile expire 7 days after consent, so JobWeaver detects expiry and shows a re-login reminder before the next hand-off. If the Gmail API is unavailable, the fallback is a Gmail compose link with recipient, subject and body pre-filled, and the PDF attached by hand (compose links cannot carry attachments).

**Considered and rejected:** sending directly via `gmail.send` (removes the User's final check in their own mail client), compose-link only (no attachment, more manual work on every application), reading replies to automate the tracker (needs a further restricted scope; out of V1).

**Consequences:** `gmail.compose` is a **restricted** scope (checked 5 Oct 2026), so a public launch needs Google verification plus an annual third-party security assessment (CASA). The cheaper public path is `gmail.send`, which is only "sensitive" (verification, no assessment) but sends directly and cannot create drafts, so it would change this decision; that choice belongs to the launch gate (ADR-0012), not V1. Gmail tokens are encrypted at rest.
