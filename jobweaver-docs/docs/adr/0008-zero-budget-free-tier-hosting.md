# Zero budget: one free web service kept warm, in-process scheduler

JobWeaver runs entirely on free tiers with no payment method attached anywhere, so nothing can bill. One web service serves the API and the built frontend (one URL, no CORS). Free hosts sleep after about 15 minutes idle, so an external monitor (UptimeRobot) pings a lightweight `GET /health` (no database access) every 5 minutes. Scheduled Fetch Runs and reminders run in an in-process scheduler (APScheduler) on that warm instance, as background work, never inside one long HTTP request. If the host still sleeps, an external free cron calling a secret-protected trigger endpoint is the fallback. The web service runs on Render's free tier (512 MB RAM, 750 instance hours a month, sleeps after 15 minutes idle). The database is **Neon's free Postgres with pgvector** (1 GB per project, scales to zero, never expires), not Render's free Postgres, which becomes inaccessible after 30 days and is deleted on day 44 (checked 5 Oct 2026). `/health` does not touch the database, so Neon sleeps between jobs and stays within its monthly compute hours.

**Considered and rejected:** separate worker and queue services (a second free service doubles the sleep problem), paid tiers (zero budget).

**Consequences:** zero budget applies to a one-month trial; afterwards paid tiers may be adopted per service, and nothing in the design depends on staying free. All Users run on the founder's shared keys. Jobs must be idempotent and resumable after a restart; long Fetch Runs are chunked; free-tier limits of each host are listed in `COSTS.md` and must be checked when choosing providers (some free databases expire or pause).
